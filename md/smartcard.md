## 1. Executive Summary & Core Principles

The **MedScout Smart Health Card** (*My Health Card*) is a **secure personal context and report-access layer** designed to streamline hospital discovery and clinical consultations. It does **not** seek to replace government identity systems like **ABHA (Ayushman Bharat Health Account)**. Instead, it serves as a patient-controlled discovery profile and temporary consent gateway.

### Core Architectural Principles

1. **Zero-Storage on Card**: The physical or digital card never stores raw medical records, lab PDFs, or full health histories. The card is strictly an identity and authorization key.
2. **Zero-PHI in QR Codes**: QR codes generated by MedScout contain **ephemeral, cryptographic authorization tokens**, never unencrypted patient health information (PHI). Anyone intercepting or photographing the QR cannot extract medical data without authorized backend verification and mutual consent.
3. **Explicit, Granular Consent**: The patient selects which specific diagnostic records to share, with which hospital, and for what time duration (e.g., 15 minutes, 1 hour, 24 hours).
4. **Immediate Revocation**: The patient can unilaterally revoke hospital access at any moment with immediate invalidation of the authorization token.
5. **No Autonomous Diagnosis**: The platform's AI Assistant processes uploaded diagnostic summaries only to explain clinical terminology and suggest matching hospital specialities—never to produce automated medical diagnoses.

## 3. Data Models & Schemas

### 3.1. Smart Health Card Profile (Embedded in User)

```typescript
interface SmartHealthCardProfile {
  cardToken: string;            // e.g., "MSC-7F2A9C1D"
  cardStatus: "ACTIVE" | "SUSPENDED";
  locationPreference: {
    city: string;               // e.g., "New Delhi"
    state: string;              // e.g., "Delhi"
    maxDistanceKm: number;      // e.g., 250
    source: "user_explicit" | "profile_derived";
  };
  budgetPreference: {
    maxCeilingINR: number;      // e.g., 350000
    payerScheme: string;        // e.g., "PM-JAY Standard", "Commercial TPA"
  };
  savedHospitalIds: string[];
  abhaReadiness: {
    status: "NOT_CONFIGURED" | "READY_FOR_CONSENT_FLOW" | "LINKED";
    storesIdentifiers: false;   // Explicit assurance: never stores Aadhaar
  };
}
```

### 3.2. Medical Report Record

```typescript
interface MedicalReport {
  id: string;                   // e.g., "rep_1727083812000"
  userId: string;               // Owning patient user ID
  title: string;                // e.g., "Comprehensive Lipid Profile & HbA1c"
  category: "Laboratory" | "Cardiology" | "Radiology" | "Pathology" | "Discharge Summary";
  reportDate: string;           // ISO YYYY-MM-DD
  provider: string;             // e.g., "Dr. Lal PathLabs, New Delhi"
  clinicalSummary?: string;     // Key non-confidential findings (e.g. "Elevated LDL")
  relevantCondition?: string;   // e.g., "Cardiology", "Severe Knee Osteoarthritis"
  fileType: "PDF" | "DICOM/PDF" | "IMAGE";
  status: "private" | "ai_shared" | "hospital_shared";
  activeGrant: ReportAccessGrant | null;
  createdAt: string;            // ISO 8601 timestamp
}
```

### 3.3. Report Access Grant (Ephemeral Consent)

```typescript
interface ReportAccessGrant {
  grantId: string;              // e.g., "grant_1727084120000"
  grantToken: string;           // Cryptographic token e.g., "MS-CONSENT-8K2A-LX9"
  recipientHospitalId: string;  // Target hospital ID or "all_verified"
  recipientHospitalName: string;// Display name of hospital/department
  grantedAt: string;            // ISO 8601 timestamp
  expiresAt: string;            // ISO 8601 timestamp (now + durationMinutes)
  durationMinutes: number;      // 15 | 60 | 1440
  status: "active" | "expired" | "revoked";
}
```

## 4. Ephemeral QR Code Protocol & Token Lifecycle

### 4.1. Token Generation Flow

1. Patient selects a specific report and clicks **"Share QR"**.
2. Patient configures the target facility (e.g. *Sir Ganga Ram Hospital*) and duration (e.g. *15 Minutes*).
3. Backend generates an unpredictable, high-entropy token:
   $$\text{GrantToken} = \text{MS-CONSENT-} \parallel \text{RandomNonce}_{32} \parallel \text{Timestamp}$$
4. A transient grant record is created with an `expiresAt` timestamp.
5. The frontend renders a QR code encoding **only the token URI**:
   `https://medscout.in/consent/verify?token=MS-CONSENT-8K2A-LX9`

### 4.2. Verification & Revocation

- When the hospital scans the QR, the hospital portal queries `POST /api/consent/verify` presenting their institutional credentials.
- If current time $> \text{expiresAt}$ or if `status === "revoked"`, access is rejected immediately.
- The patient can click **"Revoke Access"** at any moment, setting `status = "revoked"` and immediately disconnecting access.

## 5. Security & Regulatory Compliance (DPDP Act 2023 & ABDM)

| Requirement | Implementation in MedScout |
|---|---|
| **Notice & Purpose Specification** | Consent modal specifies exact recipient hospital and limited duration before generation. |
| **Data Minimization** | Only the specific selected report is exposed; other patient reports remain locked. |
| **Storage Limitation** | Ephemeral tokens expire automatically after 15m/1h/24h. |
| **Zero Aadhaar / National ID Storing** | MedScout never requests, accepts, or stores 12-digit Aadhaar numbers or ABHA PINs. |
| **Audit Trails** | All grant creation, access verification, and revocations generate immutable audit logs. |

## 6. AI Assistant Integration & Clinical Triage Guardrails

The Smart Health Card is tightly coupled to the MedScout AI Assistant:

1. **Parameter Inheritance**: When a logged-in patient opens the AI Chatbot Drawer, the assistant inherits their preferred city, max distance radius, and budget limits automatically.
2. **Clinical Terms Translation**: If a patient uploads a report and clicks **"Discuss with AI Assistant"**, the assistant receives the extracted clinical finding (e.g., *"Grade 3 medial joint space narrowing"*).
3. **Safety Guardrail**:
   - **Allowed**: *"This report mentions Grade 3 joint space narrowing, which is commonly associated with knee osteoarthritis. Would you like to view high-volume orthopedic centers performing knee replacement in Delhi NCR?"*
   - **Prohibited**: *"You have severe osteoarthritis and must undergo surgery immediately."*

## 7. ABDM & ABHA Separation Boundary

```text
┌─────────────────────────────────────────────────────────────┐
│              ABDM (National Digital Health Spine)           │
│  - ABHA 14-digit citizen health identifier                  │
│  - Unified Health Interface (UHI)                           │
│  - Health Facility Registry (HFR)                           │
└──────────────────────────────┬──────────────────────────────┘
                               │
                      Boundary Wall / Gateway
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                  MedScout Application Layer                 │
│  - Smart Health Card (Personal discovery preferences)       │
│  - Temporary QR sharing tokens                              │
│  - Hospital comparison & evidence discovery                 │
└─────────────────────────────────────────────────────────────┘
```

MedScout acts as a **HIP / HIU (Health Information Provider / User) client node** via official ABDM sandboxes. The MedScout Smart Card is the user's interface to control their personal search and consent parameters.

## 8. API Endpoint Specifications

### User Reports Management
- `GET /api/user/reports`
  - Headers: `Authorization: Bearer <accessToken>`
  - Response: `{ success: true, total: number, data: MedicalReport[] }`
- `POST /api/user/reports`
  - Body: `{ title, category, reportDate, provider, clinicalSummary, relevantCondition, fileType }`
  - Response: `{ success: true, data: MedicalReport }`
- `DELETE /api/user/reports/:id`
  - Response: `{ success: true, message: "Medical report permanently removed." }`

### Consent & QR Token Exchange
- `POST /api/user/reports/:id/share`
  - Body: `{ recipientHospitalId, recipientHospitalName, durationMinutes }`
  - Response: `{ success: true, data: ReportAccessGrant, message: string }`
- `DELETE /api/user/reports/:id/revoke`
  - Response: `{ success: true, message: "Hospital access grant revoked." }`

### ABDM Readiness
- `GET /api/user/abha/status`
  - Response: `{ success: true, data: { status: string, configured: boolean, consentRequired: true, storesIdentifiers: false } }`
